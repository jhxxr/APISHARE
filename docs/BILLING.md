# 会话粘性、计费与配额

## 会话粘性与 Prompt Cache

多轮对话路由到不同实例会导致上游的 KV Cache（Prompt Cache）失效。API Share 采用双轨识别机制：

1. **显式请求头**：客户端传入 `X-Session-Id` 或 `X-Conversation-Id`。
2. **对话前缀指纹**：自动提取 `hash(端点 + 模型 + system 指令 + 首条 user 消息)` 动态计算指纹。

粘性关系存入 SQLite，具备滑动过期机制（默认 30 分钟，有调用自动顺延），服务重启不丢失。当粘性节点故障时，网关透明故障转移到新上游并自动刷新绑定，节点恢复后不会发生不必要的抖动回切。

## 计费优先级

`后台手动覆盖价格 > LiteLLM 官方牌价库 > 网关内置兜底表 > default (0)`。

价格库启动时同步，之后每日自动刷新，也可在后台手动立即刷新。手动价格 JSON 可选字段：

| 字段 | 说明 |
|---|---|
| `cache_read` | 缓存读取单价 |
| `cache_write` | 缓存创建单价 |
| `cache_write_1h` | 明确的 1 小时缓存创建单价 |
| `reasoning` | 推理输出单价 |
| `in_audio` / `out_audio` / `cache_read_audio` | 音频输入 / 输出 / 缓存读取单价（USD / 1M tokens） |

缺省字段继承对应的输入 / 输出单价，明确填 0 表示免费。新日志保存当次价格和费用快照，扣费与日志在同一事务提交。

## Usage 采集

原生捕获以下字段：

- OpenAI Chat：`include_usage`
- Anthropic Messages：`message_delta`
- Gemini：`usageMetadata`
- OpenAI Responses：`response.completed`

若上游不返回用量，网关调用内置 `tiktoken-go` 进行本地分词计算。普通输入、缓存读取 / 创建、明确的 1 小时缓存创建、正文和推理分别计算。

## 速度指标

每条调用记录包含：

| 指标 | 含义 |
|---|---|
| `first_token_ms` | 首字延迟，仅流式实际下发增量时才有值 |
| `duration_ms` | 总耗时，覆盖完整流式转发 |
| `latency_ms` | 上游响应头耗时 |
| 输出 TPS | 输出 Token ÷ 实际生成时长（总耗时减首字） |

非流式请求没有首字，按总耗时估算。历史日志缺少新列时，总耗时回退显示原有的响应头耗时，首字与 TPS 显示为“—”，不会伪造速度数据。公开首页展示最近 24 小时每个模型的平均输出速度（`avg_tps`），没有可测量样本时显示“—”。

## 共享池与独立配额

在后台可为密钥设置基础共享额度（如 100 USD），同时对特定昂贵模型（如 `o3-mini`、`claude-3-7-sonnet`）设置专属独立额度（如 20 USD）。独立额度仅消耗自身配额，互不挤占，用尽后返回 `402 Payment Required`。额度为 0 表示无限额。

每个 Key 还可独立设置 QPS 令牌桶与并发上限。

## 调用记录自动清理

后台「设置 → 调用记录保留」可选择 `7 天（默认）`、`30 天`、`90 天`、`180 天`、`365 天` 或 `永久保留`。网关启动后立即检查一次，之后每小时清理超过保留期的逐条调用详情（`call_logs`）；保存新的保留期后也会立即清理一次。

清理只删除明细，累计数据不受影响：删除前会先把调用次数、成功次数、输入 / 输出 Token、费用以及最后一次调用时间与状态，按“北京时间日期 × 模型”汇总进 `call_log_daily` 汇总表，汇总与删除在同一事务内完成，既不丢失也不会重复计数。因此公开首页的累计 Token / 调用次数、最近调用状态、24 小时 Uptime、30 天调用趋势以及后台的今日统计与 7 天费用图表，在明细删除后仍保持完整。

保留期通过 `settings` 表中的 `log_retention_days` 持久化，接口为 `PUT /{admin_path}/api/settings` 的 `log_retention_days` 字段（仅接受上述预设值，非法值返回 400）。

## 计费边界

以下项目尚未接入：长上下文分档、优先级 / 地区 / 加速倍率、服务端工具按次费用、缓存存储时长费用、图片 / 音视频分模态价格。详细口径见[计费审计](SUB2API_BILLING_AUDIT.md)。

HTTP 音频接口仅按上游返回的 Token usage 记账；没有 Token usage 的结果记录请求，但不按字符数或时长猜测费用。WebRTC 直连通话不经过网关，无法逐轮扣费，详见[客户端接入指南](CLIENTS.md#音频与-realtime)。
