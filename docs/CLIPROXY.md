# 内置 CLIProxyAPI

CLIProxyAPI 的 Go SDK 编入 API Share。每条 CLIProxyAPI 上游对应一个独立账号池，使用独立数据目录、内部密钥和运行进程，避免 SDK 的全局账号状态与模型目录在池间共享。所有进程均运行同一个 API Share 程序，无需安装额外核心或部署第二个容器。

## 使用

1. 打开「上游服务 → 新建上游」，选择 `CLIProxyAPI 账号池`。表单自动切换，不需要手动填写内部地址或密钥。
2. 为池子命名，选择默认代理，并添加凭据。支持一次选择多个 JSON 文件；创建前添加的文件会在保存池子后导入。
3. OAuth 提供商包括 Codex、Claude、Antigravity、Kimi 国内站、Kimi 国际站、xAI、Muse / Meta 和 Devin。授权按钮会先保存新池，再在当前上游配置内显示授权进度、设备码与回调回填。
4. Vertex AI 支持导入服务账号 JSON。已有 Codex OAuth 账号还可以在当前池内绑定 SIWC。
5. 保存后进入该池子的独立详情页，所有账号、授权、代理、模型和调度设置都在上游管理内完成。详情地址支持刷新与直接打开。
6. 在「API 密钥」中授权需要的模型，并按需设置渠道优先级、权重、模型白名单和计费价格。

远程部署时，授权后如停在 localhost 回调地址，复制浏览器地址栏的完整地址，在授权区展开「手动回填」提交。

上游列表显示账号数量和运行状态。复制 CLIProxyAPI 上游会创建独立空池并沿用模型、调度与默认代理配置；凭据需要单独授权或导入。启停一个池不会启停其他池。

账号池的「运行中」与「可接收请求」分别判断。空池、账号全部停用、所有账号冷却或不支持请求模型时不参与路由；对应账号和模型恢复可用后重新入选。就绪信息来自内置 SDK 的账号及模型状态，在后台更新，转发选择阶段不逐个发起管理请求。

CLIProxyAPI 上游不显示通用的「请求头覆盖」配置；厂商请求头由内置 SDK 管理。旧版本保存的网关请求头覆盖不再用于该类型，编辑保存时会清空。其他 API 上游仍支持固定请求头和透传规则。

### 授权恢复与重复账号

- 授权由网关后台持续处理；刷新页面、离开账号池详情或关闭浏览器不会取消授权。重新打开同一池时恢复设备码、授权链接和等待状态；新账号授权完成后自动入池，不依赖浏览器轮询触发写入。
- 账号已存在时暂停写入，显示「更新原账号凭据」。确认后保留原文件名、代理绑定、启停状态、标签、权重和模型规则，更新凭据；不同账号的同名文件不会相互覆盖。直接导入 JSON 使用相同的确认规则。
- 重复识别优先使用账号 ID、提供商和组织信息，其次使用邮箱或 JWT 中的稳定账号标识；Kimi 国内站、国际站分开识别。厂商凭据没有稳定账号标识时只能检查文件名，不能保证识别不同文件中的同一账号。
- 授权会话只对发起它的管理员会话及对应池开放。过期、主动取消后清理临时进程；**网关程序重启会中断未完成的授权，需要重新发起**。已经入池的凭据不受影响。

### 账号诊断与固定账号测试

点击账号行的「详情 / 测试」，查看当前可调度状态、凭据刷新时间、账号与模型冷却倒计时及厂商返回的额度数据。额度未返回时显示未知，不补造剩余额度；额度反馈只展示经过筛选的数值、时间和已知状态。

模型列表来自当前账号的模型注册信息。选择可用模型后可发送一条简短测试请求，固定使用该账号和它的代理；失败时不会用其他账号代测。测试消耗少量厂商额度，并计入该账号 Uptime，结果显示成功与否、HTTP 状态及耗时。

### 主动查询厂商剩余额度

账号详情的「剩余额度」会主动查询独立用量接口，默认使用紧凑额度条展示前两个窗口的剩余比例和重置倒计时；额外窗口、绝对重置时间和详细用量收在「用量与重置详情」中。Codex、Claude 按返回值区分 5 小时、每周、每月及模型专属窗口；Kimi 国内站和国际站分别查询短时、周和月额度；Antigravity 展示模型组窗口；Devin、Muse / Meta 和 xAI 按各自返回的周期及账单字段展示。窗口没有使用比例或绝对余量时显示「未获取」，不会推算可调用多少次，也不会在重置倒计时结束时直接填成 100%。

读取逻辑参考原版 `Cli-Proxy-API-Management-Center` 的额度实现，核对提交为 `714de0760a3ce86094b178fb46f834d34bc4a2a5`。请求由服务端通过当前账号池的私有 v8 `requests/api-call` 发出，使用目标账号的授权及代理；浏览器不下载原始凭据，也不能传入查询 URL。查询不发送模型推理请求，不消费额度重置积分。不同订阅是否提供某个窗口仍取决于厂商，付费账号没有可读的额度接口时会明确显示未获取或查询失败。

同一账号的并发查询合并，每池最多同时查询 3 个账号，并有短时防连点和一分钟缓存。手动刷新失败时可保留上次成功数据并标为旧数据；换成另一个账号后不会沿用旧额度。停止池子不会因查询而启动，网关重启后重新查询；原有调用响应中的额度反馈收在「最近调用返回的额度反馈」中。查询过的账号在列表 Uptime 下方显示简短余量。

### 批量管理与池内调度

账号池工作区分为「账号管理」「授权与导入」「池内调度」。账号支持状态、提供商、账号代理筛选、只看异常、名称与备注搜索，以及名称、可用状态、账号优先级、成功率、失败次数、最近调用排序。列表每页 50 条，多选全选只选择当前页，筛选变化后保留已经选择的账号。账号详情可以编辑显示名称和备注，重新授权及迁移均保留这些设置。

批量启用、停用、刷新凭据、更换代理、迁移和文件导入由网关后台执行。上传并创建任务后，刷新、离开详情、关闭浏览器均不影响后续执行；重新打开同一池可恢复任务进度，在「任务记录」中切换最近任务。逐项结果保存在网关数据库，凭据输入保存在对应池的私有 `operation-inputs/` 目录，任务接口不返回原始凭据；全部成功后删除输入文件。可以取消尚未开始的项，正在进行的迁移会先核对两边状态；也可只重试失败或取消项。重复账号显示待确认，确认后保留原账号配置更新凭据。新建池可以先暂存 JSON 文件，保存上游后统一上传并后台导入；无效文件不会阻止其他文件。

网关重启后，未完成的启停、代理和导入任务会恢复；结果未确认的凭据刷新不会自动重复调用厂商，而是提示手动重试。每个池的后台任务顺序执行，执行中、待确认或恢复中的任务会阻止删除关联池。旧的同步批量管理 API 保持兼容，新的界面使用后台任务 API。

迁移先停用源账号，将凭据以停用状态复制到目标池并确认落盘，再移除源账号并恢复原启停状态。目标池已有同一账号或同名文件时不覆盖，源账号保留。原账号的优先级、权重、标签、SIWC、地区和代理选择随迁移保留；「跟随池子默认代理」在迁移后使用目标池默认代理。两池均需运行才能迁移。

迁移阶段记录在 `cliproxy_migrations` 中，不包含令牌。接口超时、网关重启后先核对两侧文件及本次迁移标记：源文件已经移除时完成目标池恢复；源文件仍在且需要回退时，先确认源账号已恢复，再清理本次创建的目标副本。源凭据发生其他变更或文件无法读取时不擅自删除，任务显示恢复中的原因，后台继续核对。已停止的池也能完成安全的文件核对与回退，不会自动启动用户手动停止的池。

「池内调度」支持轮询、加权轮询、优先消耗及会话固定。账号的「调度与服务」可设置优先级和权重：先从最高账号优先级选择可用账号，同级账号再应用池内策略；权重仅在加权轮询时决定比例。上游之间的优先级、权重与这里的账号设置相互独立。

调度页分别说明「先选上游池：数值越小越优先」及「再选池内账号：数值越大越优先」，可按模型预览当前优先级层及预计分配比例。预览使用当前可用账号快照；模型支持、实时冷却及会话固定仍可能改变实际分配。

Vertex AI 服务账号导入时优先保留文件已有的地区；文件缺少地区时使用导入设置，默认 `us-central1`。只有明确勾选「覆盖文件中已有的地区」时才用本次设置替换文件值。账号详情仍可修改地区，支持推荐列表以外的有效地区名称及 `global`。Codex 账号展示 SIWC 未绑定、有效、失效及真实到期时间，并提供重新绑定入口；这是本地凭据检查结果，不代表厂商承诺账号一定可用。

### 账号调用记录

账号详情的「调用记录」展示实际执行账号、模型、HTTP 状态、失败类别、耗时、首 Token 延迟（核心有返回时）及输入／输出 Tokens。同一次网关请求在池内或多个池之间重试时，使用统一请求编号串起各次尝试；上游调用日志详情也可查看这条尝试链。

每个池将账号尝试记录保存在自己的 `account-uptime.db`，保留 7 天；记录来自启用此功能后的实际调用，不补造历史账号归属。记录不包含请求正文、账号令牌、代理密码或厂商错误正文。使用量由核心异步写入，刚结束的请求可能需要稍后刷新查看。账号移入其他池后，原池的历史保留在原池数据库；删除整个池后，统一查询不再包含该池。

### 出站代理

在上游配置内选择「池子默认代理」，并可在账号列表中为每个账号分别指定出口。支持 HTTP、HTTPS、SOCKS5、SOCKS5h 及用户名密码认证；也可在此直接新建或编辑代理。

- 默认代理写入该池的 `config.yaml`；账号单独指定的代理写入对应凭据的 `proxy_url`。变更通过核心管理接口热加载。
- 池子的「系统默认连接」按进程环境（`HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`）出网。
- 账号支持「跟随池子默认代理」、「直接连接（不使用代理）」或指定一个已保存代理。修改池子默认代理只影响跟随默认值的账号。
- OAuth 使用独立的临时授权进程，通过本次为账号选择的代理完成授权与令牌交换，再把凭据导入当前池；不会临时切换其他账号的出口。临时授权在完成、取消或过期后清理。
- 账号池渠道自身的「请求代理」不参与该出口：该渠道只连接本机回环地址，真正出网的是核心。
- 代理被池子或账号引用时不能直接删除或停用；代理连接信息更新时会同步到关联账号。
- 代理密码不会出现在后台状态、代理列表或日志中。

网关保留鉴权、配额、限流、统计和渠道故障转移；SDK 负责 OAuth 凭据、刷新、池内账号调度及厂商适配。四种模型协议按客户端格式交给 SDK，避免重复跨协议转换。转发的会话标识按网关 API Key 隔离；核心启用池内会话粘性。

在各自上游配置中启停当前池；主动停止后，下次重启网关也保持停止。普通 API 上游不依赖这些核心。核心只监听本机回环地址，管理密钥不会发到浏览器；管理操作验证当前池，不提供通用管理 API 透传。

池进程意外退出时，由网关按 1、2、4 秒间隔最多自动恢复 3 次；连续失败后暂停恢复并显示原因，需要手动启动。稳定运行满一分钟后重新获得恢复次数。自动恢复期间可手动停止，停止偏好持久化；网关退出不会触发恢复。恢复中的进程就绪前不会使用旧的就绪快照接收请求。恢复逻辑位于接入层，没有修改 CLIProxyAPI SDK 源码。

### 每账号 Uptime

账号池专属页的账号列表显示每个账号近 24 小时的 Uptime、24 格小时轨迹及成功次数。点击轨迹可查看该账号的成功／失败次数、最近调用时间和每小时明细；数据每 30 秒刷新。手机端使用账号卡片，同时展示账号状态与 Uptime。

- Uptime = 成功尝试 ÷ 总尝试。池内重试按实际执行的账号分别统计；无调用时显示灰色和「—」，不视为 100%。
- 统计来自 SDK 的执行结果，流式请求中途失败也记为失败；令牌计数与可识别的客户端取消不参与统计。
- 历史保存在各自池子的 `account-uptime.db`，停止池子和重启网关后仍可查看。保留最近 48 小时的结果，页面展示其中最近 24 小时。
- 只保存账号标识、时间和成功／失败，不保存请求内容、令牌或错误正文。账号级统计从启用此功能后的调用开始累计，旧的上游日志不补造账号归属。

## 数据与部署

默认数据目录为 SQLite 文件所在目录下的 `cliproxy-data/`。Docker 使用原有 `/data` 持久卷，无需增加端口或卷：

- `state.json`：内部连接密钥、监听端口和启动偏好。
- `config.yaml`：核心配置。
- `auths/`：由 SDK 保存、刷新账号凭据。
- `pools/pool-*/`：新增账号池各自的状态、配置与凭据目录。与上游的绑定保存在网关数据库中。
- `account-uptime.db`：每个池目录中的账号调用结果；数据库及其 WAL 文件随同该目录持久化。

升级后，原有共享池会绑定到现有上游；已有账号尚未接入上游时会创建默认上游。历史复制出来的共享渠道会迁移为持有独立凭据快照的池。迁移保留原数据目录，重复启动不会反复创建默认上游。

升级时保留整个数据目录。新程序会加载同一份账号和配置，不覆盖已有配置。

可选环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `CLIPROXY_DATA` | 数据库所在目录的 `cliproxy-data` | 内置核心持久化目录 |
| `CLIPROXY_PORT` | `18317` | 首次初始化时的内部回环监听端口；后续使用状态文件中已保存的端口 |

## 随 API Share 发版升级

版本由根目录 `go.mod` / `go.sum` 锁定，后台展示实际编译进去的模块版本。程序运行时没有核心下载、独立升级或自动更新入口。

维护者升级依赖：

```powershell
go get github.com/router-for-me/CLIProxyAPI/v8@v8.x.y
go mod tidy
go test ./...
go build -trimpath -ldflags="-s -w" -o apishare.exe ./cmd/apishare
```

将 `v8.x.y` 替换成拟发布的具体版本，验证 OAuth 流程、原生工具调用、流式取消和 usage 口径，再按 API Share 原有流程发布二进制或 Docker 镜像。依赖版本和适配改动随同一提交评审。用户只更新 API Share。

SDK 公共接口、管理 API 或大版本变化仍需要适配与回归，不能保证任意上游版本直接替换。回退整个 API Share 版本前应备份数据目录，并检查上游是否迁移过配置或凭据格式。

接入层位于 `internal/cliproxy`，后台路由位于 `cmd/apishare/cliproxy.go`。上游源码不作本地修改，避免长期维护 fork。
